PR artifact provenance is separate from a final-main attestation. Preserve the
existing unsigned/unnotarized DMG and ad-hoc-signed Hardened Runtime App
classification. Artifact availability or signature integrity does not establish
Apple trust, first-launch acceptance or real-provider behavior.

CI schedules the release gate before UI smokes and requests at most two UI
runners at once to reduce hosted macOS capacity contention. All five scenarios
remain required for this acceptance; a skipped UI job after a failed release
gate is not a passing result. The release gate runs on native arm64 macOS 15;
UI smokes run on standard Intel macOS 15, with Providers first, after repeated
arm64 hosted-runner acquisition failures. Both use the same pinned Xcode 16.4;
test assertions and timeouts are unchanged. Packaging still verifies both
arm64 and x86_64 slices.

## Cloud combination coverage

Use temporary preferences/files, injected clocks, fake provider clients and
synthetic inputs. Automated checks must not start a real Claude CLI, inspect
credentials, install into a daily-use App location or modify real notification
permissions. Track the implemented cases in the PR rather than asserting that
every future scenario below has already passed.

- A: application Settings/Command-comma opens one Dashboard with the popover
  closed; repeated invocation reuses it and restores minimized state. Navigation
  adds no quota/CLI request. Token first-load remains separately accounted for.
- C: new, duplicate, absent-field, expired and malformed bridge input; bounded
  health record, cross-process write limit, installation revalidation, unreadable
  or unavailable health, old installation/late process and matched cleanup.
  Activity cannot update quota time, adopt a producer or generate alerts.
- D: exact 600-second boundary, fifty-minute cache, future time, clock rollback,
  reset expiry, weekly-only report, source fallback, notification watermark and
  consistent cached/history presentation across views.
- E: default-off zero automatic CLI calls; eligible recent report suppresses
  automatic reads; old duplicates/heartbeat/pending producer do not. Cover shared
  trigger admission, sixty-second minimum, 1/2/5/10/15-minute cooldown, interval
  edits, option toggles, manual outcomes, retirement and late completions.
- Combined: cooldown plus new passive data; reset plus sleep/wake; generation
  change while both bridge and CLI work finish; missing five-hour data without
  repeated requests; thirty-minute checks with ten-minute display expiry; all
  providers disabled while Settings remains reachable.

## Maintainer-local acceptance — pending

The maintainer performs this after the cloud-verified PR is Ready. Record the
candidate App identity/hash, exact macOS and Claude versions, date, actions
actually performed and any limitations. Cloud synthetic tests do not substitute
for these observations. Do not perform real account reads merely to complete
an unchecked item without the maintainer choosing that action.

- [ ] Verify the candidate version/build and source-bound package before any
  installation. Keep the previous installed App recoverable and avoid running
  both installation locations at once.
- [ ] With the popover closed and floating window hidden, direct keyboard events
  to Codex94 and press ⌘,. Verify a populated Dashboard and no empty Settings
  window; repeat with Dashboard open, closed and minimized.
- [ ] Confirm the previous Dashboard section/frame survives, repeated commands
  reuse one window, and ⌘, in another app is unaffected.
- [ ] Exercise Tab/Shift-Tab, Space/Return and Esc on the production App's actual
  controls. Record keyboard, accessibility/AXPress and tooltip observations
  separately; instrumented Recovery evidence is not a substitute.
- [ ] Review English and Simplified Chinese health text: original quota time,
  recently recorded bridge activity, waiting/unavailable states, cached values,
  explicit one-time action and automatic cooldown are distinguishable.
- [ ] If an existing statusline connection is present, verify the original
  command/output still works; choose whether to test preview/install/remove in
  an appropriate isolated setup. Old installation activity must not be mistaken
  for the current connection. Do not remove user settings as test cleanup.
- [ ] Observe ordinary Claude Code use, if desired: new report arrival, unchanged
  values, idle session and expired windows. Re-reading local files or recording
  activity must not make old quota appear newly fetched.
- [ ] With automatic CLI off, verify ordinary local refreshes stay passive. If
  the maintainer chooses to test the warned single-read action, record exactly
  what was run and whether the result was accepted.
- [ ] If the maintainer chooses to enable automatic CLI, observe the selected
  check interval, recent-data reuse, sleep/wake and recovery behavior. Record
  actual calls/data age; do not infer account-wide rate limits from local counts
  or deliberately cause provider failures.
- [ ] Confirm ordinary Codex monitoring, Token first load, floating window and
  notification preferences remain usable. Notification permission/delivery tests
  require the maintainer's choice and are not implied by UI rendering checks.

First-launch Gatekeeper/Open Anyway behavior is a separate distribution check;
do not remove quarantine or disable Gatekeeper. This local checklist does not
authorize merge or publication. Once local acceptance is recorded, subsequent
release stages still follow their own authorization and source/artifact checks.
