## 1. 更新目标与范围

### 1.1 用户可以得到什么

1. 在现有服务页直接看懂：现在显示哪份额度、报告是什么时候取得的、为什么没有更新，以及下一步能做什么。
2. 清楚地区分“重新读取本地报告”和“用 CLI 读取一次”，避免为了查看状态而意外启动 CLI。
3. 读取失败后，可以在应用内看到最近一次 CLI 尝试的结果和失败阶段，主动复制已脱敏的诊断信息。
4. 上游 CLI 改变终端格式后，维护者可以用固定样本复现问题，并确认修改没有破坏已覆盖的格式和来源切换规则。

### 1.2 本期包含

- Claude 来源健康卡及其只读展示模型；Codex 继续使用现有连接状态、失败原因和恢复入口。
- 一个明确的 Claude 本地报告重读动作，独立于 CLI 自动读取开关。
- 将已有 CLI 结束诊断接入内存状态、诊断页和用户主动复制的诊断文本。
- 按场景组织的合成回放样本、生产解析路径测试、少量真实子进程集成回放。
- Claude 来源与请求生命周期的确定性事件序列测试，保留 Codex 发现取消的交叉回归。
- 对应中英文文案、现有 UI smoke 扩展、文档和候选验收。

### 1.3 本期不包含

- 模型选择列表、首次启动向导、通知静音、Token 新图表。
- OAuth、多账号、新额度来源、自动登录、Claude 直接 HTTP 额度请求。
- 改变轮询频率、数据新鲜度阈值、来源选择优先级或通知阈值。
- 持久化诊断历史、额度时间序列、遥测上传或自动提交问题报告。
- 自动安装更新、签名与公证改造、发布产物保留策略调整。

## 3. 来源健康与恢复指引

### 3.1 信息布局

以 **Dashboard → 服务**作为完整入口，升级已有 Claude 来源区域，依次展示：

1. **当前显示**：本地用量缓存 / 状态栏连接 / CLI 报告 / 暂无可用报告。
2. **数据状态**：当前报告、缓存报告或上次用量记录；显示原始报告时间及年龄。
3. **当前操作**：读取中、正在结束上次读取，或最近一次读取结果。
4. **原因与下一步**：简短解释和适用操作。

“数据是否可用”和“最近一次操作是否成功”必须分开。CLI 尝试失败但本地报告仍有效时，继续展示本地报告，并单独说明此次尝试失败。

弹窗只保留简短状态和“查看来源详情”入口，打开现有服务页；不复制完整的状态栏配置界面。诊断页提供更详细的固定字段和原有复制能力。

### 3.2 展示模型与所有权

建议新增 `Codex94/Support/ClaudeSourceHealthPresentation.swift`，作为纯展示投影。具体类型名可在实现中调整，职责固定：

- 输入为 store 已持有的已接受报告、时间、缓存检查状态、安装状态、待确认标记、CLI 操作状态及诊断摘要。
- 输出为数据状态、操作状态、主说明 key、次要提示及允许的动作枚举。
- 使用显式 `now` 计算年龄；不读文件、不创建任务、不调用 CLI、不修改偏好或通知基线。
- 报告内容和新鲜度结论复用现有 `ClaudeQuotaFreshnessPolicy` 与历史投影，不重新实现来源选择。
- 不向视图暴露账号 UUID、producer 指纹、installation ID、完整路径或原始终端文本。

当前已接受的完整报告在 Store 内部。需要补充信息时，新增窄的纯只读 accessor，例如 `sourceHealthInput(at:)`，返回展示所需的值；不得为了获取展示状态调用会评估通知的 `projectReport`。不能仅由 `lastIssue == .staleData` 推断报告新鲜度，因为操作错误可能与旧报告同时存在。

建议新增 `Codex94/Views/Components/ClaudeSourceHealthView.swift`，接收投影与窄动作闭包。由 `ProviderSettingsView` 负责接线；操作仍由 Store 与既有设置组件执行。

不为 Codex 新建另一套诊断采集器。健康入口需要显示 Codex 时，复用现有连接状态和跳转；本期深入解释三来源状态的对象是 Claude。

### 3.3 状态与动作矩阵

下表的文案为语义示例，实际通过 `Localizable.xcstrings` 提供中英文。

| 事实条件 | 显示内容 | 适用动作与限制 |
| --- | --- | --- |
| Claude 监控关闭 | “Claude 监控已关闭”；来源检查状态为未检查 | 指向现有启用开关；不展示旧检查结果为当前状态 |
| 有新鲜的已接受报告 | 来源、原始报告时间及当前额度 | 可以重新读取本地报告；CLI 单次读取保持独立并保留警告 |
| 有可显示但已陈旧的报告 | “正在显示缓存报告”；保留原始时间 | 解释本地重读不会让云端数据变新；提供明确操作 |
| 所有共享窗口已过期，仅有历史投影 | “上次用量记录，当前额度未知” | 展示历史来源时间；不得显示恢复到 100% 或触发恢复通知 |
| 没有任何已接受的可用报告 | “暂未取得可用报告” | 按已知检查状态解释；可重读本地或主动 CLI 读取 |
| 本地缓存 absent | “未发现本地用量报告” | 说明需要 Claude Code 自己获取报告；不得推断退出登录 |
| 本地缓存 unreadable / invalid | “本地报告暂时无法读取/解析” | 保留已有有效来源；提示稍后重读和查看诊断，不猜测权限或格式变化的具体原因 |
| 本地缓存 valid，但另一来源被选中 | “已读取本地报告，当前显示另一份被接受的报告” | valid 不等于新鲜或最新；不为未选来源编造精确时间 |
| 状态栏未安装 / 已安装 | 分别说明安装状态，与是否收到报告分开 | 未安装不等于 Claude 服务失败；已安装不等于账号已验证或已取得报告 |
| 状态栏报告需要确认 | “检测到尚未采用的报告来源” | 跳转现有采用确认；仍验证 frozen confirmation ID，不能直接采用 |
| 状态栏配置冲突或属于另一目录 | 分别说明已有配置冲突或原配置目录不一致 | 跳转既有设置处理；不自动搬迁、覆盖或移除另一目录中的配置 |
| CLI 正在读取 | “正在读取”；旧报告继续按其原状态展示 | 禁止重复单次读取，不增加排队请求；不伪造实时细分阶段 |
| CLI 正在退役 | “正在结束上次读取” | 复用 `isRetiringCLI` 禁用读取；等待旧请求和 shutdown 均结束 |
| 最近 CLI 尝试失败 | 失败原因、最近一次结束阶段与耗时 | 展示诊断；仅在用户点击后再试一次，保持原有警告 |
| 官方 CLI 明确返回需要登录 | “CLI 提示需要登录” | 引导用户在官方客户端处理；不能将其扩展成所有来源都已退出登录 |
| 单次 CLI 读取成功，另一个来源仍被选中 | “本次读取完成”；单独显示当前实际来源 | 成功不等于该报告必须覆盖更新的本地/状态栏报告 |

主说明选择规则：监控关闭时先说明关闭；其余情况先展示已接受的数据状态，再叠加操作状态和来源问题。来源待确认与配置冲突不能将仍有效的另一来源抹成“无数据”。

### 3.4 “重新读取本地报告”的准确语义

基线的 `ClaudeQuotaStore.refresh(trigger:)` 在自动 CLI 开关开启时可能启动 CLI，因此**不能直接作为本地重读按钮的实现**。

计划新增窄入口，例如 `rereadPassiveSources()`：

1. 检查监控已开启且 store 尚未停止。
2. 复用现有本地缓存安全读取、状态栏报告加载、来源资格检查和报告投影。
3. 按既有规则更新已知状态；确实检测到账号/安装上下文变化时，继续执行现有失效和退役逻辑。
4. 不主动调用 `startCLIRead`，不增加自动 CLI intent。上下文不变时，不提前或延后既有后台/Reset 截止时间；可以重新投影“下次尝试”显示。确实检测到身份失效时，保留现有 Reset 清理、轮询重建和截止时间重算规则。
5. 新的被动观测按原有资格和通知去重规则处理，不引入第二套通知逻辑。

测试隔离独立定时器后，验证无论 CLI 自动开关开或关，点击本地重读的 CLI 启动增量都为零。若已有独立自动任务到期，其行为必须与该按钮分开记录。

### 3.5 其余恢复动作

| 动作 | 接线方式 | 验收重点 |
| --- | --- | --- |
| 用 CLI 读取一次 | 复用 `AppStore.readClaudeOnceWithCLI()`、`ClaudeReadOnceActionView` 与 `canReadOnceWithCLI` | 不改变自动读取偏好；双击不追加读取；忙碌/退役时不可用 |
| 处理来源确认 | 定位到 `ClaudeStatuslineSetupView` 中现有采用流程 | 继续显示确认说明，旧对话框不能采用已替换或过期报告 |
| 处理安装问题 | 定位到现有安装预览、冲突或移除区域 | 保留预览、用户动作和事务保护，不新增快捷覆盖 |
| 查看诊断 | 打开现有诊断页 | 浏览和相对时间刷新不新增额度请求 |
| 复制诊断 | 复用原有用户触发的复制按钮 | 复制固定字段，保留分享前检查提示，不自动上传 |

页面渲染不得新增 provider RPC/CLI 或额度缓存写入。现有设置页的只读安装状态检查可以保留；测试应区分这种检查与额度刷新，避免把“页面零新增请求”错误写成“页面绝不读取任何配置”。

## 4. 应用内 CLI 诊断

### 4.1 数据边界

只保留当前上下文中最近一次已完成读取的 `ClaudeCLIUsageDiagnostic`，不建立事件历史。沿用现有字段：

| 字段 | 类型/语义 |
| --- | --- |
| `phase` | 结束时所处阶段，固定枚举 |
| `result` | success / failure / cancelled |
| `issue` | 既有 `ClaudeQuotaIssue` 或无错误 |
| `usage_sent` | 是否发送过内建 usage 操作 |
| `terminal_received` | 是否收到终端输出 |
| `duration_ms` | 单调时钟计算的耗时 |

最近读取结束时间沿用既有时间语义，但必须按 readID 与该次诊断绑定成一致记录后再发布/导出；不能将一个独立的“最近诊断”与当前 `lastCLIReadAt` 临时拼接。诊断尚未到达时，显示本次结果处理中，或保留明确标注的上一条完整记录。内部请求 ID 与 generation 仅用于隔离，不展示、不复制、不记录到 OSLog。

不加入原始错误文本、终端片段、RPC、额度数值、账户标识、配置内容或私人路径。OSLog 保持现有每次读取一个结束事件的行为，接入应用内展示不能导致重复记录。

### 4.2 生命周期和并发规则

现有 `diagnosticHandler` 在 client 初始化时注入，但自动模式会复用 client。实施时必须在**每次 fetch 边界**绑定观察回调，不能只在 client 创建时捕获 generation。

建议设计：

1. 每次 `startCLIRead` 通过准入后生成内部 `readID`，捕获当前 generation。
2. 在 fetch 调用边界传入窄的 per-read observer；保留默认 OSLog 和已有 fake fetcher 的简洁注入方式。
3. 诊断回调回到 MainActor 后，同时验证监控状态、generation 和最近启动的 readID。
4. readID 保留到下一次读取或上下文失效，避免 fetch 已返回而诊断回调稍后到达时丢失正确结果。
5. 新请求开始时显示“读取中”；若保留上一次结束摘要，明确标注为上一次，不冒充当前实时阶段。
6. 监控关闭、真正的身份/上下文失效和 shutdown 时清理相关摘要，并拒绝迟到回调。
7. CLI 开关变化导致的退役继续遵循 4.1.8 的通知连续性；清理诊断不能重置同账号通知基线。
8. 取消不是新的用户错误；旧请求的 cancelled 事件不能覆盖新请求的成功或失败。

这一期只展示结束阶段；若将来需要实时细分进度，应另行设计事件频率和生命周期，不能从最后一次结束事件推测当前进度。

### 4.3 必须补充的测试

- 同一 client 连续两次读取，诊断分别归属于正确 readID。
- 成功结果先发布、诊断回调后到达，仍能保留该次有效摘要。
- 读取完成与诊断回调按两种顺序到达时，摘要和结束时间始终来自同一次读取；第二次读取的时间不能配上第一次诊断。
- 旧 generation 的诊断在关闭/重启后到达，不进入界面或复制文本。
- 新请求开始后旧请求回调到达，不覆盖新请求状态。
- 失败后重试期间，旧报告和上次失败仍有明确标识；成功后再更新结论。
- 诊断导出仅含允许字段；内部请求身份与合成敏感哨兵均不泄露。

## 5. CLI 兼容性回放样本

### 5.1 样本组织

以 [CLI_COMPATIBILITY.md](../CLI_COMPATIBILITY.md) 为准；下面保留原设计范围供逐项核对。

### 5.2 样本 schema

| 字段 | 要求 |

| `schemaVersion` | 独立于 App 版本；校验未知版本并明确拒绝 |

| `referenceTime`、locale、timezone | 固定时间和解析条件；日期不依赖执行当天 |
| `events` | 有界输出块、虚拟时间推进、输入断言、退出/取消等事件 |
| `expected` | 报告/错误、允许输入动作、次数、结束诊断与清理结果 |
| `tags` | 可选，供 focused suite 选择场景 |

事件数据只包含合成内容。控制序列用 JSON 转义，UTF-8 边界由测试驱动切分；少数非法字节用有界字节数组，不需要可执行脚本字段。

加载器使用现有标准库，不新增第三方运行时依赖。样本正文不得插入 shell 源码、`eval` 或任意命令；运行假 CLI 时只允许测试驱动预定义的动作。

schema 校验应拒绝重复 ID、非法引用、路径逃逸、超限事件/字节数和未知动作。有效上限场景及超限拒绝场景由驱动生成，不能为了测试而放宽生产 1 MiB 输出限制。

### 5.3 最小场景清单

| 组别 | 本期必需场景 | 关键预期 |
| --- | --- | --- |
| Claude 正常流程 | 已有普通 prompt、framed prompt、ready footer、必要终端查询 | 只在完整且被识别的状态发送允许输入；usage 命令只发送一次 |
| 报告内容 | 只有 5 小时、只有每周、双窗口、小数百分比、模型标题干扰 | 保留真实字段语义，缺失不补零，不将模型标题误作共享窗口 |
| 终端输出 | 连续重绘、清屏、分块、UTF-8/ANSI 截断、同步更新未闭合 | 不完整帧不能授权输入或复用旧报告；完整后可继续 |
| 新鲜度 | refreshing 后完成、持续 refreshing、报告改变后稳定 | 不接受 refreshing 中旧值；保持 1 秒报告稳定要求 |
| 未知界面 | 登录/引导、陌生 prompt、未知 trust、非自有目录 trust | 无模型提示输入、无猜测性确认；明确失败或超时 |
| 超时/边界 | 无输出、连续输出、输出超限、进程提前退出 | 总期限不被持续重绘延长；错误分类与清理正确 |
| 取消 | 启动前、等待 prompt、usage 已发出、已有子进程树 | 不再发送输入；所有拥有的进程按既有策略停止 |
| Codex 发现 | 正常候选、不兼容候选回退、显式手动路径失败、队列取消 | 手动路径保持权威；取消后不启动后续版本探测 |
| Codex RPC | 从现有测试提取成功、畸形响应、超时/退出代表样本 | 使用生产解码路径；不得将传输失败误作零额度 |

对短握手与控制序列做逐字节切分；对完整报告做固定切点和固定随机种子的有限组合，避免无界排列导致 CI 时间膨胀。

纯时序测试明确覆盖现有 100 ms 评估节拍、200 ms 动作稳定、1 秒报告稳定及默认 20 秒 usage 读取阶段期限的边界，不改变这些生产阈值。版本检查有独立的最长 3 秒预算，usage deadline 在 PTY 启动后建立，进程清理仍有自身预算；不能将它们合并成整个 fetch 必须在 20 秒内完成的新承诺。真实 PTY 测试使用合理时间范围和上界，不断言某个精确的实际毫秒耗时。

### 5.4 分层复用与时间控制

1. **纯解析/决策层**：尽量直接调用现有生产 parser。只有调度判断当前不可测试时，才提取最小纯 decision helper，显式传入单调时间和完整屏幕状态；不能在测试中复制生产解析规则。
2. **客户端集成层**：少量关键样本驱动假 CLI / PTY，验证真实 reader、允许输入、超时与进程组清理。继续用短的有界真实超时；不要用虚拟时钟宣称验证了 OS 进程终止。
3. **Store 层**：复用注入的 `now`、`sleep` 和受控 fetcher，通过 barrier/continuation 精确安排完成顺序，不依靠长 sleep 或轮询碰运气。
4. **UI 层**：只选代表性状态进入现有 Providers/Recovery smoke；不在 UI runner 里重复全部样本矩阵。优先共享样本 ID 与预期语义，需要共享文件时显式复制允许的合成资源。

墙上时间与单调时间分开注入：parser 和 Store 使用固定 wall time；真实客户端集成如需断言具体重置日期，为其日期解释增加默认仍为 `Date()` 的窄 wall-clock 注入。未注入固定日期的 PTY 用例只断言与日期无关的行为。真实 I/O 超时继续使用真实单调时钟，不改变宿主系统时间。

测试失败日志只输出样本 ID、步骤、固定类别与断言差异，不自动打印全部 transcript、RPC 或环境。样本自身作为经过审查的测试源码保存，不作为 release/UI 下载附件打包。

### 5.5 兼容性记录

`docs/CLI_COMPATIBILITY.md` 分开记录三种证据：

- **合成格式回放**：样本 ID、参考格式、生产测试路径、通过的 source revision。
- **隔离 UI 场景**：假 CLI 标识、场景、候选版本、截图与 CI 身份。
- **真实 CLI 验收**：只有实际执行后才填写 CLI 版本、macOS、候选身份、日期和已验收操作；未做时标记未验证。

假 CLI 声称 `2.1.999` 或某个参考版本，不构成该真实版本的兼容证明。单个版本验收也不能推广为整个版本区间受支持。本期不加入运行时版本封锁或未经验证的兼容警告。

## 6. 状态切换测试

### 6.1 每一步都检查的不变量

1. 同时最多一个 Claude CLI 读取；退役中的旧 client 及 fetch 尾部结束后才能启动新 client。
2. generation 已过期的结果和诊断不得更新快照、历史、偏好、缓存、提醒或界面。
3. 当前显示始终来自一份合格报告；时间相同时遵循现有来源优先级，不混合百分比。
4. 文件重读和重复状态栏报告不能更新原始报告时间。
5. 同账号 CLI 开关或安装退役不重置通知基线；旧观测回退不重放提醒。
6. 真正账号/来源上下文变化仍按现有规则失效；安装身份不能替代账号身份。
7. 待确认报告的 ID、安装上下文和有效期必须匹配，旧对话框不能采用新报告。
8. 历史报告不进入当前额度提醒或 Reset 调度；无数据、缺失和零保持不同语义。
9. 关闭 Codex 只停止其额度/Token 生命周期，不影响 Claude；关闭 Claude 不停止 Codex。
10. 诊断展示、导航和纯投影不产生新的读取、通知或安装副作用。

### 6.2 必需事件序列

| ID | 事件序列 | 验证重点 |
| --- | --- | --- |
| S01 | 本地新报告 → 更近的状态栏报告 → 更旧来源回退 | 来源选择正确，通知观测水位不倒退 |
| S02 | 自动 CLI 读取中 → 开关关闭 → 旧成功/诊断返回 → 再开启 | 旧结果失效、同账号基线保留、仅一个后续自动意图 |
| S03 | 手动单次读取 → 连续点击 → 开关变化 → 清理结束 | 一次明确操作不排队追加单次读取 |
| S04 | 监控关闭 → 立即重启 → 旧请求与新请求分别完成 | 旧请求和诊断不能更新新一轮状态 |
| S05 | 已知账号 A → 账号 B → A 的 CLI 迟到 → B 报告过期 | 不复活 A 的报告或借用其通知基线 |
| S06 | 暂时 JSON 写入不完整 → 下一次安全读取成功 | 不把短暂读失败当成确定账号变化 |
| S07 | 状态栏卸载/重装 → 旧安装报告到达 | 正确安装隔离，同账号通知连续性不受影响 |
| S08 | 打开采用确认 → pending 报告被替换/过期 → 点击旧确认 | 旧确认不产生采用效果 |
| S09 | 手动/后台/Reset 同时到期 → 请求跨越 Reset → 时钟回退 | 保持单次在途和既有 Reset 覆盖/失败消耗规则 |
| S10 | 所有窗口过期 → 历史展示 → 收到新有效报告 | 历史不制造恢复值，新数据自然恢复当前状态 |
| S11 | Codex 探测排队/执行中 → 关闭 → 下一候选 → 重新开启 | 取消覆盖完整发现事务，新的查找仍可复用 |
| S12 | CLI 成功先完成 → 诊断回调迟到 → 下一读取启动 | 诊断正确归属；不因任务已结束误丢最后有效摘要 |
| S13 | 自动 CLI 开关分别开/关 → 点击本地重读；分别返回同上下文与身份失效结果 | 两个分支中按钮自身启动 CLI 次数均为零；上下文不变时不改期，身份失效时保留现有清理/重建规则 |

先实现命名序列并检查每一步结果，再加入有限、固定种子的事件组合。发现新回归时增加最小序列；不得用单一最终快照替代中间状态和调用次数断言。

## 10. 风险、控制与回退

| 风险 | 控制方式 | 回退范围 |
| --- | --- | --- |
| 健康卡把来源检查失败误判为账号退出 | 只基于明确枚举和已接受报告；无数据不等于登录失效 | 单独撤回投影/文案，不修改读取规则 |
| “本地重读”意外走到 CLI | 独立窄命令，自动开关两态均断言 CLI 启动增量为零 | 移除该新入口，保留原刷新行为 |
| 迟到诊断污染新一轮读取 | 每次 fetch 绑定 readID + generation，序列测试覆盖回调顺序 | 撤回内存展示接线，保留现有 OSLog |
| 测试提取改变实际解析/时序 | 先保留现有测试，仅增加最小测试接缝；关键行为用真实 PTY 合成集成回归 | 分离并撤回生产重构，保留能独立运行的测试 |
| 样本数量导致 CI 变慢或不稳定 | 短消息全切分、长消息有限切点；固定种子、受控完成、少量子进程用例 | 缩小昂贵组合，保留命名关键回归 |
| UI/Recovery 资源缺失或意外打入 App | 显式 test target membership、Bundle 检查、逐项 BUILD_INPUTS | 回退资源集成提交，不扩大目录复制 |

本期目标是不新增持久化偏好和缓存 schema。按上述设计回退应用代码不需要数据迁移；已存在的 4.1.8 statusline 安装兼容规则仍然适用。
